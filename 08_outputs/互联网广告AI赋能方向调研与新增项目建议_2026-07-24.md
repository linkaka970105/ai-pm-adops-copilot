# 互联网广告 AI 赋能方向调研与新增项目建议

> 调研日期：2026-07-24
> 调研对象：汇量科技（Mobvista）、钛动科技（Tec-Do）、有米科技/有米云，以及 Moloco、AppLovin、Liftoff、Unity、Google Ads、Meta Ads、TikTok Ads 等行业公司。
> 目标：为现有 `AdOps Copilot` 之外新增 1–2 个 AI 产品项目，优先考虑与本人广告投放系统后端开发、产品经理经历和有米现有资源的匹配度。
> 证据说明：公司规模、产品效果和客户案例数字均按“公司公开披露/官网自述”处理，不视为独立审计结论，更不能直接写成个人项目结果。

---

## 1. 结论先行

### 1.1 最建议新增的两个项目

#### 项目一：AI 创意实验与增长学习 Agent

它不是“AI 生成广告素材”，而是补齐广告创意的完整增长闭环：

```text
外部广告情报 + 企业历史素材 + 创意级投放数据
→ 多模态拆解
→ 提出可证伪的创意假设
→ 生成受控变量与实验矩阵
→ 回收 CTR/CVR/CPI/ROAS
→ 识别有效元素和混杂因素
→ 生成下一轮 Creative Sprint
```

选择理由：

- 能复用有米公开的 AppGrowing 广告情报、创意管家 DAM 和投后复盘能力。
- 与 AdOps Copilot 的投放异常/归因排障明显不同。
- 能同时体现多模态理解、生成式 AI、实验设计、数据分析、反馈闭环与安全审核。
- 公开素材和模拟实验数据可以支撑个人 PoC，不必伪造公司内部数据。

#### 项目二：全球 ASO 与本地化增长 Agent

它利用公开的 App Store/Google Play 页面、评论、关键词、竞品素材和国家规则，生成关键词机会、评论洞察、本地化文案、视觉 Brief、政策风险和商店页 A/B 测试路线图：

```text
商店页 + 用户评论 + 关键词 + 竞品素材 + 国家/品类规则
→ 多语评论聚类与用户痛点
→ 关键词和竞品机会
→ 本地化文案与视觉 Brief
→ 政策/文化风险检查
→ A/B 测试路线图与结果复盘
```

选择理由：

- 能复用有米公开的 ASOGrow、AppGrowing Global 和海外 App 增长资源。
- 与 AdOps Copilot 几乎不重合，能补充多语 NLP、用户研究、本地化和实验能力。
- Google Play/App Store 页面、公开评论和竞品数据更容易支撑可信 PoC。
- 离线结果不能声称已提升关键词排名或自然下载，最终效果仍需真实上线实验。

### 1.2 有条件的高价值替代方向

如果能确认本人确实接触过媒体 SDK、Offerwall/SpinGo、广告位或变现指标，并能合法获得脱敏样本，可将第二项目升级为：

**AI 媒体变现与用户体验优化 Agent**

它站在流量主/开发者侧，在广告收入、留存、IAP 和用户体验之间做多目标优化。这个方向业务和算法含金量更高，但当前数据可做性只有 2/5；未确认真实经历或合法数据前，只适合作为“概念方案 + 仿真 PoC”，不应声称已上线。

### 1.3 不建议直接做的项目

- 通用 AI 文案/图片/视频生成器：行业已高度商品化，差异化弱。
- “全链路营销超级 Agent”：范围过大，容易只有聊天界面和概念图。
- 黑盒全自动出价平台：没有大规模 auction、conversion 和 LTV 数据，很难自证。
- 单独再做 SDK 排障、素材政策审核、客户回复：已在 AdOps Copilot 第二阶段范围内，重复度高。
- 把有米、汇量或钛动的公开产品写成自己的真实工作项目：除非能确认本人实际参与和可自证贡献。

## 2. 已确认的个人背景与项目边界

### 2.1 仓库材料确认的事实

- 2020-05 至 2023-03：有米科技广告投放系统后端开发。
- 2023-04 至 2025-06：有米科技广告投放系统产品经理。
- 当前重点作品 `AdOps Copilot` 已覆盖：
  - 投放效果异常诊断；
  - 平台、MMP、客户后台归因数据不一致核对；
  - 低风险知识查询；
  - 后续扩展讨论过 SDK/API 深排、素材审核和客户回复。

### 2.2 当前无法确认、不能默认写成个人经历的内容

- 是否参与过 AppGrowing、有米有数、创意管家、ASOGrow、SpinGo 或 Offerwall。
- 是否负责过广告变现、媒体 SDK、ASO、创意数据、投放算法或反作弊模块。
- 是否能合法使用内部事件字段、历史投放结果、客户素材或业务指标。
- 公司公开的产品效果、客户案例是否与本人工作有直接关系。

因此，新增项目在简历和作品集中必须明确属于以下哪一类：

1. **真实工作项目复盘**：需要本人角色、决策、结果和证据。
2. **基于公司资源的产品概念方案**：可以体现业务理解，但不能说已上线。
3. **个人 PoC/作品集项目**：可以使用公开数据、脱敏样例和明确标注的模拟数据。

## 3. 重点公司 AI 方向

### 3.1 汇量科技：预测 AI、投放自动化、创意生成与企业 Agent 四层并进

| 层次 | 产品/方向 | 可核验能力 | 关键判断 |
| --- | --- | --- | --- |
| 实时预测与竞价 | Mintegral Smart Bidding | Target ROAS、Target CPE、Hybrid ROAS、IAP ROAS；根据深层事件和价值预测动态出价 | 商业成熟度最高。2025 年公司披露智能竞价贡献 Mintegral 超过 80% 收入，但不代表所有客户 ROI 提升 80% |
| 跨渠道运营自动化 | XMP | 多平台数据、MMP/变现接入、批量建广告、24 小时盯盘、预警、开关、预算/出价调整、日志 | 公开功能的核心仍有大量规则引擎和阈值自动化，不宜夸大为完全自主 Agent |
| 创意生产 | Playturbo | 链接生图、数字人视频、图片转视频、AI 配音/翻译/消除、批量裂变和尺寸适配 | 真正值得借鉴的是“生成—投放—效果回流”，而不是单点生成 |
| 企业工作流 | Mr.Max / MaxAgent | 多 Agent 任务拆解、工具调用、SOP/知识、CSV/Excel 分析；公司材料报告其用于邮件处理、数据分析和创意 | 公开证据主要是内部实践，是否标准化外售仍需谨慎表述 |
| 数据与增长 | SolarEngine | 归因、ROI、用户行为、在线参数、A/B 测试、反作弊 | 公开证据更强的是数据底座；不能直接断言已有成熟 LLM 决策助手 |

汇量在 2025 年业绩材料中明确提出：

- 程序化模型继续承担毫秒级、高频广告交易决策。
- LLM/Agent 更适合策略分析、创意制作、广告计划管理和工作流编排。
- 两者是分层协同，而不是让大模型直接替代实时竞价模型。

这条架构原则非常适合写进新增项目：**LLM 负责目标、解释、编排和复盘；规则/预测模型负责确定性约束与实时决策。**

### 3.2 钛动科技：从投放 SaaS 升级为垂直多模态模型 + 营销多智能体

钛动的公开演进路径较清楚：

```text
全球媒体/达人资源 + Tec-Ad 投放 SaaS
→ Tec-Creative 2.0 创意生产与资产能力
→ “钛极”营销多模态模型
→ Navos 营销多智能体
→ Agent Builder、GEO/GEM 等后续规划
```

#### 当前可核验的能力

| 产品 | 能力 | 数据/资源底座 |
| --- | --- | --- |
| Tec-Creative 2.0 | 创意洞察、图片/视频、数字人、语音、本地化、资产管理、批量变体、效果回流 | 历史素材、商品数据、平台规格、地区文化和投放表现 |
| Navos 咨询 Agent | 市场趋势、竞品定位、创意雷达、营销策略 | Google Trends、TikTok Creative Center、Amazon 等公开/授权数据 |
| Navos 创意 Agent | 多模态解构、创意效果归因、标杆派生、本地化生成 | 素材元素、完播/互动/转化、行业 Know-how |
| Navos 优化 Agent | 自然语言目标转配置、跨市场批量复制、异常预警、效果报告、预算和创意建议 | Meta、Google、TikTok、Snap 等媒体 API 与投放数据 |
| 钛极模型 | 营销策略、视频理解、视频生成；按行业路由并结合 CTR/CVR/ROI 反馈 | 公司披露的广告策略、SPU、结构化创意问答与营销素材数据 |

钛动官网及港交所申请稿披露，2025 年服务 10 万+广告主、累计管理 4 亿+广告策略，资源网络包括约 700 万家媒体发布商/流量媒体和 1.5 亿+达人。这些是公司披露口径。其所谓 “AI marketing solutions” 收入主要仍来自广告花费/效果相关服务费，不能等同为纯 AI SaaS 订阅收入。

#### 对项目设计的启发

- 模型不是壁垒本身，**可归因的投放反馈、跨区域资源和行业 Know-how** 才是。
- 多 Agent 的价值不在于角色数量，而在于洞察、创意、投放和反馈是否共享同一事实与数据状态。
- “海外市场进入与本地化洞察 Agent”是可选项目，但需要把引用、时效和跨文化风险做扎实。

## 4. 行业趋势与仍存在的机会

### 4.1 七个共性趋势

1. **预测模型 + 生成模型 + Agent 分层协同。**
   预测模型做价值和出价，生成模型做内容，Agent 做诊断、计划、执行和校验。

2. **从 Copilot 向有限 Autopilot 演进。**
   不是直接无人值守，而是按风险分级、审批、回滚和审计。

3. **创意从“生成”升级为“学习闭环”。**
   链接/商品/历史素材 → 多模态生成 → 投放探索 → 疲劳识别 → 效果回流 → 下一轮生成。

4. **优化目标从点击/安装下沉到 ROAS、LTV 和增量。**

5. **隐私环境下，信号治理成为产品能力。**
   一方事件、匿名 postback、服务端回传、去重和学习准备度决定模型效果。

6. **买方和卖方同时 AI 化。**
   广告主侧做获客、创意和预算；媒体侧做 bidding、floor、placement、format、ARPDAU 和留存。

7. **合规前移到生成和执行阶段。**
   平台政策、品牌、版权/肖像、AI 标签、敏感品类和地区差异需进入 guardrail。

### 4.2 仍有产品空间的六个问题

- 跨平台统一的边际 ROAS、预算情景和实验决策层。
- 回答“哪个创意元素在什么市场有效、为什么有效”，而不只是批量出图。
- 将广告收入和留存、IAP、投诉、差评放进同一多目标优化。
- 自动诊断事件缺失、回传延迟、去重错误和隐私框架映射。
- 自动提出可证伪假设、控制变量、样本量和停止规则。
- 同时检查文化、平台政策、功效宣称、人物/音乐/IP、AI 标签和落地页一致性。

## 6. 推荐项目一：AI 创意实验与增长学习 Agent

### 6.1 一句话定位

面向出海 App/游戏广告主和创意团队，将外部广告情报、企业历史素材与投放表现连接起来，通过多模态分析生成可验证的创意假设、受控变体和实验计划，并在效果回流后沉淀可复用的创意策略。

### 6.2 目标用户

- 创意策略负责人：需要知道下一批素材做什么，而不是只拿到“多生成几条”。
- 广告优化师：需要判断素材疲劳、市场差异和测试优先级。
- 设计/视频团队：需要清晰的 Brief、控制变量和品牌/政策约束。
- 海外增长负责人：需要看到创意、市场和 ROAS 的连接。

### 6.3 核心工作流

1. 选择产品、国家、渠道、目标事件和历史窗口。
2. 导入竞品公开素材、企业历史素材和创意级指标。
3. 多模态模型把视频/图片拆成 Hook、人物、场景、卖点、情绪、镜头、节奏、文案、CTA、BGM 等结构化标签。
4. 系统生成“可验证假设”，例如：
   - “东南亚市场真人使用场景可能比纯产品展示有更高 3 秒留存。”
   - 不能直接输出“真人场景就是高转化原因”。
5. 系统识别受众、版位、出价、渠道和时间等混杂因素。
6. 生成受控变体、Creative Brief、优先级和实验矩阵。
7. 上线前执行品牌、平台政策、本地文化和落地页一致性检查。
8. 导入实验结果，判断假设是否被支持，并生成下一轮迭代。

### 6.4 AI 与系统设计

| 能力 | 建议实现 |
| --- | --- |
| 素材理解 | 多模态大模型 + 视频抽帧 + ASR/OCR + 音频/节奏特征 |
| 相似素材与元素库 | 多模态 embedding、聚类和去重 |
| 策略知识 | 国家/渠道/品类/政策 RAG，所有政策建议带版本与引用 |
| 假设生成 | LLM 基于结构化标签和指标生成假设，禁止输出无证据因果结论 |
| 实验规划 | 规则引擎生成控制变量、样本量/最低运行窗口和停止条件 |
| 变体生成 | LLM/图像/视频工具输出 Brief 或低保真样例；MVP 不必训练生成模型 |
| 效果分析 | 分层对比、回归/倾向评分等方法；先处理混杂因素再下结论 |
| 安全 | 品牌规则、版权/肖像、敏感品类、AI 标签和人工审核 |

### 6.5 MVP 范围

- 先限定：游戏或工具 App、两个国家、一个主要渠道。
- 输入 100–200 条公开或合法脱敏素材及其人工标签。
- 支持视频/图片结构化拆解、素材聚类、假设卡、实验矩阵和下一轮 Brief。
- 使用模拟投放结果时，界面与文档始终显示“模拟数据”。
- 不在 MVP 中自动创建广告、修改预算或发布素材。

### 6.6 指标

效果指标：

- 多模态标签准确率/F1；
- 创意诊断专家一致率；
- 假设被实验支持的比例；
- 下一轮素材测试胜率；
- 有效素材率和疲劳预警 Precision/Recall。

体验指标：

- 从复盘到 Brief 的时间；
- 创意团队建议采纳率；
- 素材检索和复用效率；
- 人工修改次数。

安全指标：

- 政策风险漏检率和误杀率；
- 品牌偏离率；
- 无依据因果结论率；
- 未授权素材使用率。

业务指标：

- 创意生产周期；
- 一次审核通过率；
- 实验成本；
- 经真实在线实验验证的增量 CTR/CVR/ROAS。

### 6.7 面试可讲的产品取舍

- 为什么不直接做文生视频：生成已商品化，真正缺的是“为什么做、如何验证、如何学习”。
- 为什么不能看见高 CTR 就说某元素有效：存在受众、版位、出价和时间混杂。
- 为什么需要人审：创意涉及品牌、版权、文化、政策和虚假功效宣称。
- 为什么先输出 Brief 而不是自动发布：降低执行风险，也更适合个人 PoC。

## 7. 条件推荐项目：AI 媒体变现与用户体验优化 Agent

### 7.1 一句话定位

面向 App/Web/OEM 流量主和广告变现运营，通过预测广告收益与用户流失风险，推荐广告位、格式、频控、奖励强度和竞价/底价策略，并用实验和 guardrail 在提升收入的同时保护留存、IAP 和用户体验。

### 7.2 为什么适合有米资源

- Offerwall 已有 SDK/API、开发者对接、任务广告和报表。
- SpinGo 已有互动广告形式、用户互动和收入分析。
- 有米公开拥有广告主需求、自有 App/海外用户和开发者资源。
- 本人有广告系统后端与产品经历，更容易讲清事件、接口、策略和异常边界。

但必须确认本人是否真实接触过流量主、SDK 或变现业务；若没有，应定位为概念项目/个人 PoC。

### 7.3 核心工作流

1. 接入请求、竞价、胜出、填充、展示、点击、互动、奖励、转化和收入事件。
2. 同时接入 session、D1/D7 留存、IAP、崩溃、投诉/差评等体验信号。
3. 识别低填充、eCPM 下滑、频次过高、版位疲劳、奖励失衡或延迟异常。
4. 预测候选策略的收入提升和留存/IAP 风险。
5. 输出机会卡：
   - 当前问题和证据；
   - 建议配置；
   - 预计收益区间；
   - 留存风险；
   - 置信度和适用范围。
6. 人工审批后进入小流量实验。
7. 触发留存、投诉、崩溃等 guardrail 时自动停止并回滚。
8. 复盘实验并更新版位/国家/人群策略知识。

### 7.4 AI 与系统设计

- 时序异常检测：发现 eCPM、fill、展示和收入异常。
- 收益预测：预测不同配置下的 ARPDAU/eCPM。
- 流失/IAP 风险模型：避免用广告收入蚕食长期价值。
- Contextual Bandit：在限定探索预算下选择互动形式、奖励和频控。
- 规则/约束优化：限制儿童、敏感人群、频次、崩溃和投诉风险。
- LLM：解释证据、生成实验方案和复盘，不负责实时竞价。
- 实验平台：分流、样本量、停止规则、回滚和显著性分析。

### 7.5 MVP 范围

- 先做一个 App、两类广告位、两种互动形式。
- 使用明确标注的仿真事件流，构建收益/留存冲突场景。
- Agent 只给策略建议和实验计划，不直接修改生产配置。
- 展示多目标 Pareto 边界，而不是只给一个“最优答案”。

### 7.6 指标

- 收益：ARPDAU、eCPM、fill rate、广告收入。
- 体验：D1/D7 留存、session length、投诉/差评、关闭率。
- 长期价值：IAP 收入、LTV、广告与内购蚕食率。
- 模型：收益预测误差、流失预测 AUC/PR-AUC、策略离线价值。
- 实验：实验成功率、自动停止准确率、回滚时延。
- 安全：越权操作率、错误自动动作率、人工接管率。

### 7.7 面试可讲的产品取舍

- 为什么不能只优化 eCPM：短期收入可能伤害留存、IAP 和品牌体验。
- 为什么不用大模型直接做实时决策：广告请求需要低延迟、稳定和可约束。
- 为什么需要探索预算：新广告位/新国家存在冷启动，但探索不能无限消耗用户体验。
- 为什么先做仿真：没有合法真实事件数据时，不能把模型效果包装成上线结果。

## 8. 推荐项目二：全球 ASO 与本地化增长 Agent

### 8.1 定位

输入 App、目标国家和竞品，分析商店页、用户评论、关键词、竞品素材和当地规则，输出关键词机会、评论痛点、本地化文案、视觉 Brief、政策风险和 A/B 测试路线图。

### 8.2 核心能力

- 多语评论主题聚类、情绪和需求识别；
- 关键词意图聚类和机会优先级；
- 商店页图片/文案/评论的跨模态一致性；
- 国家/品类政策 RAG；
- 本地化改写而不是直接翻译；
- 商店页实验的假设、变量、样本量和复盘。

### 8.3 优势与风险

优势：

- Google Play/App Store、评论和竞品页面容易获得。
- 与 AdOps Copilot 几乎没有重合。
- 能体现 NLP、多语、本地化、用户研究和实验。

风险：

- 离线分析不能证明排名或自然下载提升。
- 关键词量级、转化和排名数据需要第三方工具或真实上线实验。
- 不能把有米 ASO 服务案例当作个人结果。
